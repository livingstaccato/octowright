# Octowright 0.14.2 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan.

**Goal:** Publish the merged correctness and dashboard-pairing work as a coherent `0.14.2` repository version through a final CI-gated release pull request.

**Architecture:** The release branch contains metadata and release notes only. `VERSION` remains the single canonical version source; plugin manifests mirror it; the changelog and upgrade highlights describe user-visible behavior and security boundaries without claiming stronger authentication than the implementation provides. No tag or package publication is performed unless the repository's merge automation does so.

**Tech Stack:** Plain-text `VERSION`, JSON plugin manifests, Python upgrade metadata, Markdown changelog, pytest, GitHub Actions.

---

### Task 1: Create the release branch from the fully merged main

**Files:**
- Branch metadata only

- [ ] **Step 1: Fetch and verify both feature PRs are merged**

Run: `git fetch origin`

Run: `gh pr view 100 --json state,mergedAt,mergeCommit`

Run: `gh pr view 101 --json state,mergedAt,mergeCommit`

Both states must be `MERGED` and `origin/main` must contain both merge commits.

- [ ] **Step 2: Create an isolated release worktree**

Run: `git worktree add .worktrees/release-0.14.2 -b release/0.14.2 origin/main`

### Task 2: Add a failing version-consistency assertion

**Files:**
- Modify: `tests/test_version_sync.py`
- Modify: `tests/test_upgrade.py`

- [ ] **Step 1: Extend the release metadata test**

Assert the canonical `VERSION`, runtime package version, `.antigravity-plugin/plugin.json`, `.claude-plugin/plugin.json`, and `.codex-plugin/plugin.json` all equal `0.14.2`. Assert the top changelog heading and newest upgrade-highlight entry carry the same version.

- [ ] **Step 2: Run and capture RED**

Run: `uv run pytest tests/test_version_sync.py tests/test_upgrade.py -q`

Expected: repository metadata still reports `0.14.1`.

### Task 3: Bump every version consumer and write release notes

**Files:**
- Modify: `VERSION`
- Modify: `.antigravity-plugin/plugin.json`
- Modify: `.claude-plugin/plugin.json`
- Modify: `.codex-plugin/plugin.json`
- Modify: `CHANGELOG.md`
- Modify: `src/octowright/upgrade.py`

- [ ] **Step 1: Set canonical and mirrored versions to `0.14.2`**

Change only the version fields in the canonical file and three plugin manifests. Do not broaden dependency ranges or alter marketplace ordering.

- [ ] **Step 2: Add the `0.14.2` changelog section**

Summarize the correctness batch: profile lifecycle serialization, pre-allocation URL rejection, Windows bridge-state safety, bounded discovery, visible dashboard degradation, stable terminal teardown, and deterministic frontend builds.

Summarize opt-in dashboard pairing: one-time bootstrap codes become short-lived origin-scoped bearer sessions; HTTP, SSE, WebSocket, and protected media are covered. State the trust boundary accurately: the loopback daemon and same-user lockfile remain local trust boundaries, pairing does not defend against a same-user process that can read daemon state, and remote dashboard exposure still requires explicit opt-in.

- [ ] **Step 3: Add concise upgrade highlights**

Add the newest `UpgradeHighlight` entry in `src/octowright/upgrade.py` with the same behavior and compatibility notes. Keep the structure/order used by `0.14.1` so CLI upgrade rendering remains stable.

- [ ] **Step 4: Run the version test and capture GREEN**

Run: `uv run pytest tests/test_version_sync.py tests/test_upgrade.py -q`

- [ ] **Step 5: Commit the release metadata**

Run: `git add VERSION .antigravity-plugin/plugin.json .claude-plugin/plugin.json .codex-plugin/plugin.json CHANGELOG.md src/octowright/upgrade.py tests/test_version_sync.py tests/test_upgrade.py && git commit -m "release: bump version to 0.14.2"`

### Task 4: Validate the release artifact and merge

**Files:**
- Review only: release diff and built artifacts

- [ ] **Step 1: Run repository verification**

Run: `make ci`

Run: `cd packages/octowright-frontend && npm run build && npm run test`

Run: `uv build`

Run: `git diff --check origin/main...HEAD`

Inspect the wheel with the existing wheel verification test/script and confirm its package metadata reports `0.14.2` and contains `styles.css`.

- [ ] **Step 2: Push and open the release PR**

Run: `git push -u origin release/0.14.2`

Create a non-draft PR titled `release: 0.14.2`, with a body listing the two merged PRs, verification commands, and the dashboard-pairing trust boundary.

- [ ] **Step 3: Wait for all required GitHub checks**

Run: `gh pr checks release/0.14.2 --watch --interval 10`

Inspect and fix only release-caused failures. Re-run the exact failed command locally before pushing.

- [ ] **Step 4: Merge and verify main**

Run: `gh pr merge release/0.14.2 --merge --delete-branch`

Fetch `origin/main`, verify `VERSION` is `0.14.2`, and verify the release PR state is `MERGED`. Do not create a tag or invoke a publish workflow unless separately requested.

- [ ] **Step 5: Remove local release worktree**

After the merged state and main version are verified, remove `.worktrees/release-0.14.2` and prune worktree metadata. Preserve all unrelated user files in the main worktree.
