# Octowright 0.25.0 Release Preparation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce and verify a local, publishable Octowright 0.25.0 release candidate without pushing, tagging, creating a GitHub release, or publishing packages.

**Architecture:** Keep the root `VERSION` file as the core distribution's single source of truth and synchronize the three integration manifests, release-pinning tests, changelog, and curated upgrade data to it. Leave the independently versioned terminal plugin at 0.1.1, then verify both distributions and their dependency metadata from built artifacts.

**Tech Stack:** Hatchling/build, Python/pytest, JSON plugin manifests and upgrade highlights, Keep a Changelog, uv, npm/Vitest/Vite.

```markdown
## [Unreleased]

Merged but not yet shipped. At the next version bump this heading becomes that
version and a fresh empty `[Unreleased]` takes its place; the holding pen

## [0.25.0] - 2026-09-20

### Added
- **Chromium sessions can opt out of the automation-controlled browser signal
  when a site rejects automated sign-in.** Set
  `disable_automation_controlled: true` at launch to add Chromium's
  `--disable-blink-features=AutomationControlled` switch. The option defaults
  to `false`, accepts only a strict boolean, is rejected for Firefox and WebKit,
  and persists across relaunch, handoff, and HTTP relaunch paths. It changes
  only Chromium's automation-controlled signal; Octowright's title, status,
  emoji, viewport, recording, and other browser behavior remain enabled.

### Fixed
- **Short or common identity/context macro arguments no longer corrupt replay
  recordings** (#247). Blind value replacement now defaults to credential-tier
  arguments only, while every classified key remains structurally redacted.
  `OCTOWRIGHT_MACRO_BLIND_SCRUB_POLICY=all` preserves the previous
  maximum-privacy behavior, and `=reject` refuses identity/context arguments
  before browser or artifact side effects. Runtime diagnostics, session
  ledgers, screenshots, artifact reports and generated scripts share the same
  strict policy.

### Security
- **Source checkouts now resolve AsyncSSH 2.24.0 or newer on supported
  platforms**, closing CVE-2026-62949 in the terminal plugin's SSH dependency.
  The floor is a uv-only constraint, not a dependency published by core or the
  terminal plugin. Windows ARM64 keeps its existing resolution because the
  patched AsyncSSH release requires a Cryptography version with no installable
  wheel on that platform.
```

- [ ] **Step 4: Inspect wheel metadata for dependency-boundary regressions**

Run:

```bash
uv run python - <<'PY'
from email.parser import Parser
from pathlib import Path
from zipfile import ZipFile

def requirements(wheel: Path) -> list[str]:
    with ZipFile(wheel) as archive:
        metadata_name = next(name for name in archive.namelist() if name.endswith(".dist-info/METADATA"))
        metadata = Parser().parsestr(archive.read(metadata_name).decode())
    return metadata.get_all("Requires-Dist", [])

core = next(Path("dist").glob("octowright-0.25.0-*.whl"))
terminal = next(Path("dist-terminal").glob("octowright_terminal-0.1.1-*.whl"))
core_reqs = requirements(core)
terminal_reqs = requirements(terminal)
assert not any(req.lower().startswith("asyncssh") for req in core_reqs)
assert not any(req.lower().startswith("provide-uterm") for req in core_reqs)
assert not any(req.lower().startswith("asyncssh") for req in terminal_reqs)
assert any(req.lower().startswith("provide-uterm") for req in terminal_reqs)
print("distribution dependency boundaries verified")
PY
```

Expected: `distribution dependency boundaries verified`. AsyncSSH remains a workspace lock constraint rather than either package's direct published dependency; the terminal package continues to depend on provide-uterm independently.
