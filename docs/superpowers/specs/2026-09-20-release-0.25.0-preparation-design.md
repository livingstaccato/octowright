# Octowright 0.25.0 Release Preparation Design

## Objective

Prepare the already-implemented Chromium sign-in compatibility option and
macro privacy fix for a local Octowright 0.25.0 release candidate. This work
updates release metadata and validates publishable artifacts; it does not push,
tag, create a GitHub release, or publish to an index.

## Version scope

- Bump core `VERSION` from `0.24.0` to `0.25.0`.
- Bump the three repository-root integration manifests to `0.25.0`.
- Leave `octowright-terminal` at `0.1.1`. Its package code and public contract
  did not change, and the release workflow deliberately publishes it on an
  independent version line with `skip-existing`.

## Changelog contract

Promote the current `[Unreleased]` contents into a dated `0.25.0` section and
create a fresh empty `[Unreleased]` section. The release section will describe:

1. The opt-in Chromium `disable_automation_controlled` launch option, including
   its strict boolean and Chromium-only validation, persistence across relaunch
   and handoff paths, default-off posture, and Google sign-in motivation.
2. Issue #247's replay-safe macro privacy policy: credential-only blind
   scrubbing by default, structural redaction for every classified field, and
   configurable `credentials`, `all`, and `reject` modes across runtime and
   generated artifacts.
3. The source-checkout AsyncSSH security floor, explicitly noting that it is a
   uv-only constraint rather than a published direct dependency and that
   Windows ARM64 retains its compatible resolution.

The compare links will make `[Unreleased]` start at `v0.25.0` and add the
`0.25.0` comparison against `v0.24.0`.

## Upgrade notice

Add `src/octowright/upgrade/highlights/0.25.0.json` with two concise,
benefit-first entries:

- Google sign-in can opt out of Chromium's automation-controlled signal.
- Short/common identity values no longer corrupt macro recordings by default.

The dependency-resolution change remains in the changelog rather than the
interactive upgrade banner because it does not change an installed wheel's
declared dependencies.

## Verification

After the metadata changes:

- Run the plugin-version and upgrade-highlight guards.
- Run the repository's complete `make ci` gate against version 0.25.0.
- Run the terminal plugin and frontend suites.
- Build core and terminal wheels and sdists, validate packaged dashboard
  assets, and inspect wheel metadata to confirm neither distribution gained a
  direct AsyncSSH dependency.
- Confirm the working tree is clean after committing the release preparation.

Remote multi-platform CI, tagging, and publication remain separate steps that
require pushing the local commits.
